# PM Role Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `PM` (site manager) role that can run sites, Gantt/Kanban, assignments, teams and leave, sees POs/inventory without prices, and can never read money, with the money block enforced by the database.

**Architecture:** PM is a sibling of ADMIN. The database gets three new helpers: `is_pm()`, `is_site_staff()` and `can_manage_teams()`. Site-ops RLS policies move from `is_admin_or_owner()` to `is_site_staff()`. Money policies stay unchanged, so PM is denied by default. Tables that mix ops and money columns (`sites`, `workers`, POs, inventory) are never readable by PM directly. PM reads them through SECURITY DEFINER `pm_*` RPCs that return price-free columns, and edits sites through `pm_update_site()`. On the frontend, a pure `src/lib/roles.js` module decides capabilities. A module-level current-role store lets the data hooks switch to the `pm_*` RPCs, and pages hide money sections behind `canSeeMoney(role)`.

**Tech Stack:** React 18 + Vite, Supabase Postgres (RLS, plpgsql), Deno edge functions, vitest + jsdom.

**Spec:** `docs/superpowers/specs/2026-10-17-gantt-weighted-progress-design.md` §13. Inventory with file:line for every role check: `docs/superpowers/specs/2026-10-17-pm-role-inventory.md`.

## Global Constraints

**Roles and access**
- Role value is exactly `'PM'`. The label shown in the UI is `PM (ผู้จัดการโครงการ)`.
- PM sees **all sites**.
- PM sees **no money anywhere**: contract value, costs, incomes, expenses, invoices, quotations, cheques, salaries, daily rates, PO prices, stock costs, the money S-curve, financial KPIs and billing %.
- PM sees POs and inventory read-only and without prices or costs.
- PM counts as an **admin seat** (`'admins'` seat kind).
- PM gets ops notifications and can approve leave. PM gets no money notifications: cheque reminders and quotation follow-ups.
- PM can manage worker teams.
- ADMIN behaviour is unchanged by this plan.
  - Exception: ADMIN cannot save PLAN or record quantities. That rule belongs to Part B and is **not** in this plan.
- OWNER behaviour is unchanged.
- WORKER behaviour is unchanged.

**Database**
- `is_admin_or_owner()` must not change.
- Every new SECURITY DEFINER function:

- In policies, wrap row-independent helper calls as `( SELECT fn() )`. This is the initplan pattern from `2026-10-17-02-rls-initplan-wrap.sql`.
- Migrations live in `supabase/migrations/`. They are applied with `npx supabase db query --linked -f <file>`.

## Review Focus

1. **A PM reading a money table directly.** Examples: `supabase.from('incomes')`, `from('site_financial_summary')`, an embed `workers(monthly_salary)`. The DB must return zero rows or null embeds, not data. Task 1 and Task 2 SQL tests check every money table.
2. **A PM tab gate keyed on `permKey`.** `supplier_credit_notes` and `supplier_tax_invoices` share permKey `purchase_orders`, so a permKey-based allowlist would leak them. Task 3's test pins that PM cannot open them.
3. **Unknown role or page falling back to `'edit'`** in `getPageLevel`. For PM the fallback must be `'none'`. Task 3 test.
4. **A PM page that crashes on missing money fields.** Examples: `site.contract_value.toLocaleString()`, or `.single()` on a view PM cannot read. Tasks 4–7 each load the page as PM in a jsdom smoke test.
5. **Team policy subquery reading `workers` under PM's RLS.** PM cannot see `workers`, so an `EXISTS (SELECT … FROM workers)` inside a policy is always false. Task 2 replaces that subquery with the SECURITY DEFINER `worker_in_my_tenant(uuid)`. Its SQL test inserts a team member as PM.

```sql
-- Spec: docs/superpowers/specs/2026-10-17-gantt-weighted-progress-design.md §13
BEGIN;

ALTER TABLE user_roles DROP CONSTRAINT user_roles_role_check;
ALTER TABLE user_roles ADD CONSTRAINT user_roles_role_check
  CHECK (role = ANY (ARRAY['OWNER','ADMIN','PM','WORKER']));

CREATE OR REPLACE FUNCTION public.is_pm() RETURNS boolean
  LANGUAGE sql STABLE SECURITY DEFINER SET search_path = public
AS $$ SELECT COALESCE(current_user_role() = 'PM', false) $$;

CREATE OR REPLACE FUNCTION public.is_site_staff() RETURNS boolean
  LANGUAGE sql STABLE SECURITY DEFINER SET search_path = public
AS $$ SELECT COALESCE(current_user_role() IN ('OWNER','ADMIN','PM'), false) $$;

CREATE OR REPLACE FUNCTION public.can_manage_teams() RETURNS boolean
  LANGUAGE sql STABLE SECURITY DEFINER SET search_path = public
AS $$ SELECT COALESCE(current_user_role() IN ('OWNER','PM'), false) $$;

REVOKE ALL ON FUNCTION public.is_pm(), public.is_site_staff(), public.can_manage_teams() FROM PUBLIC, anon;
GRANT EXECUTE ON FUNCTION public.is_pm(), public.is_site_staff(), public.can_manage_teams() TO authenticated;

-- Seats: PM uses an admin seat.
CREATE OR REPLACE FUNCTION public.tenant_under_seat_limit(p_kind text, p_inclusive boolean DEFAULT false)
 RETURNS boolean LANGUAGE plpgsql STABLE SECURITY DEFINER SET search_path TO 'public'
AS $function$
DECLARE
  v_tenant_id UUID := current_tenant_id();
  v_limit NUMERIC;
  v_count NUMERIC;
BEGIN
  SELECT CASE p_kind
    WHEN 'admins'  THEN p.max_admins
    WHEN 'workers' THEN p.max_workers
    WHEN 'sites'   THEN p.max_sites
  END INTO v_limit
  FROM tenants t
  LEFT JOIN packages p ON p.id = t.package_id
  WHERE t.id = v_tenant_id;

  IF v_limit IS NULL THEN
    RETURN true;
  END IF;

  CASE p_kind
    WHEN 'admins' THEN
      SELECT count(*) INTO v_count FROM user_roles
      WHERE tenant_id = v_tenant_id AND role IN ('OWNER','ADMIN','PM');
    WHEN 'workers' THEN
      SELECT count(*) INTO v_count FROM workers WHERE tenant_id = v_tenant_id;
    WHEN 'sites' THEN
      SELECT count(*) INTO v_count FROM sites
      WHERE tenant_id = v_tenant_id AND status = 'Ongoing';
  END CASE;

  RETURN CASE WHEN p_inclusive THEN v_count <= v_limit ELSE v_count < v_limit END;
END;
$function$;

CREATE OR REPLACE FUNCTION public.tenant_seat_status()
 RETURNS TABLE(kind text, used bigint, max_allowed integer)
 LANGUAGE plpgsql STABLE SECURITY DEFINER SET search_path TO 'public'
AS $function$
DECLARE
  v_tenant_id UUID := current_tenant_id();
  v_max_admins INT;
  v_max_workers INT;
  v_max_sites INT;
BEGIN
  SELECT p.max_admins, p.max_workers, p.max_sites
  INTO v_max_admins, v_max_workers, v_max_sites
  FROM tenants t LEFT JOIN packages p ON p.id = t.package_id
  WHERE t.id = v_tenant_id;

  RETURN QUERY SELECT 'admins'::TEXT,
    (SELECT count(*) FROM user_roles WHERE tenant_id = v_tenant_id AND role IN ('OWNER','ADMIN','PM')), v_max_admins
  UNION ALL SELECT 'workers'::TEXT,
    (SELECT count(*) FROM workers WHERE tenant_id = v_tenant_id), v_max_workers
  UNION ALL SELECT 'sites'::TEXT,
    (SELECT count(*) FROM sites WHERE tenant_id = v_tenant_id AND status = 'Ongoing'), v_max_sites;
END;
$function$;

ALTER POLICY owner_inserts ON user_roles WITH CHECK (
  ( SELECT is_owner() ) AND tenant_id = ( SELECT current_tenant_id() ) AND ( SELECT tenant_can_write() )
  AND (role <> ALL (ARRAY['OWNER','ADMIN','PM']) OR tenant_under_seat_limit('admins')));
ALTER POLICY owner_updates ON user_roles WITH CHECK (
  ( SELECT is_owner() ) AND tenant_id = ( SELECT current_tenant_id() ) AND ( SELECT tenant_can_write() )
  AND (role <> ALL (ARRAY['OWNER','ADMIN','PM'])
       OR EXISTS (SELECT 1 FROM user_roles old WHERE old.id = user_roles.id AND old.role = ANY (ARRAY['OWNER','ADMIN','PM'])))
       OR tenant_under_seat_limit('admins'));
```

```sql
BEGIN;
CREATE OR REPLACE FUNCTION public.pm_sites()
RETURNS TABLE(id uuid, site_number text, name text, short_name text, status text, start_date date, end_date date,
              client_id uuid, client_name text, location text, map_url text, lat numeric, lng numeric,
              distance_km numeric, travel_minutes numeric, is_default boolean, notes text, created_at timestamptz)
LANGUAGE sql STABLE SECURITY DEFINER SET search_path = public
AS $$
  SELECT s.id, s.site_number, s.name, s.short_name, s.status, s.start_date, s.end_date,
         s.client_id, COALESCE(c.name, s.client_name), s.location, s.map_url, s.lat, s.lng,
         s.distance_km, s.travel_minutes, s.is_default, s.notes, s.created_at
  FROM sites s LEFT JOIN clients c ON c.id = s.client_id
  WHERE s.tenant_id = current_tenant_id() AND is_site_staff()
  ORDER BY s.created_at DESC
$$;

CREATE OR REPLACE FUNCTION public.pm_update_site(p_site_id uuid, p_patch jsonb)
RETURNS void LANGUAGE plpgsql SECURITY DEFINER SET search_path = public
AS $$
DECLARE k text;
  allowed text[] := ARRAY['name','short_name','status','start_date','end_date','location','map_url','lat','lng','distance_km','travel_minutes','notes'];
BEGIN
  IF NOT is_site_staff() OR NOT tenant_can_write() THEN
    RAISE EXCEPTION 'not allowed' USING ERRCODE = '42501';
  END IF;
  FOR k IN SELECT jsonb_object_keys(p_patch) LOOP
    IF NOT k = ANY (allowed) THEN RAISE EXCEPTION 'field not allowed: %', k USING ERRCODE = '22023'; END IF;
  END LOOP;
  -- Ongoing seat rule from the sites admin_updates policy
  IF p_patch ? 'status' AND p_patch->>'status' = 'Ongoing'
     AND NOT EXISTS (SELECT 1 FROM sites WHERE id = p_site_id AND status = 'Ongoing')
     AND NOT tenant_under_seat_limit('sites') THEN
    RAISE EXCEPTION 'site seat limit reached' USING ERRCODE = '54000';
  END IF;
  UPDATE sites s SET
    name           = CASE WHEN p_patch ? 'name' THEN p_patch->>'name' ELSE s.name END,
    short_name     = CASE WHEN p_patch ? 'short_name' THEN NULLIF(p_patch->>'short_name','') ELSE s.short_name END,
    status         = CASE WHEN p_patch ? 'status' THEN p_patch->>'status' ELSE s.status END,
    start_date     = CASE WHEN p_patch ? 'start_date' THEN (p_patch->>'start_date')::date ELSE s.start_date END,
    end_date       = CASE WHEN p_patch ? 'end_date' THEN (p_patch->>'end_date')::date ELSE s.end_date END,
    location       = CASE WHEN p_patch ? 'location' THEN p_patch->>'location' ELSE s.location END,
    map_url        = CASE WHEN p_patch ? 'map_url' THEN p_patch->>'map_url' ELSE s.map_url END,
    lat            = CASE WHEN p_patch ? 'lat' THEN (p_patch->>'lat')::numeric ELSE s.lat END,
    lng            = CASE WHEN p_patch ? 'lng' THEN (p_patch->>'lng')::numeric ELSE s.lng END,
    distance_km    = CASE WHEN p_patch ? 'distance_km' THEN (p_patch->>'distance_km')::numeric ELSE s.distance_km END,
    travel_minutes = CASE WHEN p_patch ? 'travel_minutes' THEN (p_patch->>'travel_minutes')::numeric ELSE s.travel_minutes END,
    notes          = CASE WHEN p_patch ? 'notes' THEN p_patch->>'notes' ELSE s.notes END,
    updated_at     = now()
  WHERE s.id = p_site_id AND s.tenant_id = current_tenant_id();
  IF NOT FOUND THEN RAISE EXCEPTION 'site not found' USING ERRCODE = 'P0002'; END IF;
END $$;

LANGUAGE sql STABLE SECURITY DEFINER SET search_path = public
AS $$ SELECT EXISTS (SELECT 1 FROM workers WHERE id = p_worker_id AND tenant_id = current_tenant_id()) $$;
```

```js
// Role capabilities. PM is a sibling of ADMIN (site operations, no money), so
// pages ask "can this role do X" here instead of ranking roles in a line.
const HIERARCHY = { OWNER: 3, ADMIN: 2, WORKER: 1 }

export const ROLE_OPTIONS = ['OWNER', 'ADMIN', 'PM', 'WORKER']
export const ROLE_LABELS = { OWNER: 'เจ้าของ', ADMIN: 'แอดมิน', PM: 'PM (ผู้จัดการโครงการ)', WORKER: 'ช่าง' }

// ADMIN-level tabs a PM may open, by tab id. Never by permKey: the supplier
// credit-note and tax-invoice tabs share permKey 'purchase_orders'.
export const PM_TAB_IDS = new Set(['sites', 'site_detail', 'purchase_orders', 'inventory'])

export const isPm = role => role === 'PM'
export const canManageSites = role => role === 'OWNER' || role === 'ADMIN' || role === 'PM'
export const canSeeMoney = role => role === 'OWNER' || role === 'ADMIN'
export const canManageTeams = role => role === 'OWNER' || role === 'PM'
export const canApproveLeave = role => role === 'OWNER' || role === 'ADMIN' || role === 'PM'

export function roleMeetsTab(role, tab) {
  if (role === 'PM') return tab.minRole === 'WORKER' || PM_TAB_IDS.has(tab.id)
  return (HIERARCHY[role] ?? 0) >= (HIERARCHY[tab.minRole] ?? 0)
}

// Data hooks are plain functions without the role; App sets this once the role resolves.
let currentRole = null
export function setCurrentRole(role) { currentRole = role ?? null }
export function getCurrentRole() { return currentRole }
```
