# ทีมช่าง + กลุ่ม LINE หลายกลุ่ม — Design

สถานะ: DRAFT รอเจ้าของอนุมัติ · ยังไม่มีโค้ด · ห้ามใช้ migration กับฐานข้อมูลจริงก่อนถามเจ้าของ
Mockup: https://claude.ai/artifact/Em8v7EpU8eniwDxXCMjSVf

## 1. เป้าหมาย
1. มอบหมายงานเป็นทีมได้ (เช่น ทีมช่างไฟ ทีมช่างแอร์) ช่าง 1 คนอยู่ได้ทีมเดียว (ตัดสินใจ 2026-10-12) ลดเวลาเลือกช่างทีละคนเมื่อมีช่องหลักร้อย
2. Tenant ผูกกลุ่ม LINE ได้มากกว่า 1 กลุ่ม ทุกกลุ่มมีบอท รับรูปและรับแจ้งงานได้ ช่างไม่จำเป็นต้องอยู่กลุ่มเดียวกันทั้งหมด

ไม่อยู่ในขอบเขต: เปลี่ยนวิธีคิดเงินเดือน/ต้นทุนแรงงาน, สิทธิ์ใหม่นอกจาก "เจ้าของ"

## 2. คำตอบของเจ้าของที่ใช้เป็นฐาน
- ทีมเป็นทางลัดในการมอบหมาย ช่าง 1 คนอยู่ได้แค่ 1 ทีม จึงไม่มีกรณีช่างซ้ำระหว่างทีม
- กลุ่ม LINE ไม่ต้องมีทุกคนรวมกัน แต่ทุกกลุ่มต้องมีบอท
- ช่างที่ไม่มีทีมยังมอบหมายรายคนได้เหมือนเดิม
- แก้ทีมได้: เจ้าของเท่านั้น

### สมมติฐานที่ยังรอยืนยัน (ใช้ค่านี้ไปก่อน)
- A1 ช่างที่ชนกับกะที่มีอยู่แล้ว (วันและกะเดียวกัน ไซต์ใดก็ตาม) = ใช้กล่องยืนยันเขียนทับที่มีอยู่แล้วใน Assign.jsx (ไม่สร้างกลไกใหม่; กรณีนี้ยังเกิดได้ เพราะมอบหมายรายคนหรือเลือกทีมคนละไซต์ได้)
- A2 (ตัดสินใจแล้ว) กลุ่ม LINE ไม่ผูกกับทีมหรือไซต์ 1 tenant มีได้หลายกลุ่ม เพดานต่าง tier: Free 1, Solo 1, Pro Team 5, Business 10, Enterprise ไม่จำกัด
- A3 (ตัดสินใจแล้ว) ไม่ broadcast งานประจำวันไปทุกกลุ่ม เจ้าของเลือก 1 กลุ่มเป็น "กลุ่มแจ้งงาน" บอทส่ง push งานประจำวันเฉพาะกลุ่มนั้น กลุ่มอื่นรับรูปและคำสั่งเข้า tenant เดียวกันได้ตามปกติ

## 3. โมเดลข้อมูล (migration ใหม่ ยังไม่ apply)
```
worker_teams        (id, tenant_id, name, created_at)         unique(tenant_id, name)
worker_team_members (worker_id, team_id, tenant_id)           PK(worker_id)  -- 1 คน 1 ทีม
line_groups         (id, tenant_id, group_id TEXT, label, is_notify BOOL, created_at)   -- ไม่ผูกทีม/ไซต์
                    unique(tenant_id) WHERE is_notify  -- กลุ่มแจ้งงานได้ 1 กลุ่มต่อ tenant
packages.max_line_groups INT   -- NULL = ไม่จำกัด ต่างกันตาม tier
                    unique(group_id)   -- แทน idx_line_settings_crew_group_id (กลุ่มเดียวห้ามอยู่หลาย tenant)
```
- ทุกตารางมี `tenant_id` + RLS เหมือนตารางอื่น: อ่านได้ทั้ง tenant, เขียนได้เฉพาะบทบาทเจ้าของ
- **เพดานกลุ่มตาม tier:** ทำตามแบบ `max_admins/max_workers/max_sites` ใน `2026-08-29-14-package-seat-limits.sql` คือเพิ่มคอลัมน์ `packages.max_line_groups` และ case `'line_groups'` ใน `tenant_under_seat_limit()` ต้องบังคับฝั่งเซิร์ฟเวอร์ตอน INSERT กลุ่ม (ใน webhook) ไม่ใช่แค่ซ่อนปุ่ม tenant ที่ไม่มี package ไม่จำกัดตามกติกาเดิม และ tenant ที่มีกลุ่มเกินเพดานใหม่ไม่ถูกตัดกลุ่มเดิม แค่เพิ่มไม่ได้ ค่าเริ่มต้น: Free 1, Solo 1, Pro Team 5, Business 10, Enterprise NULL (ไม่จำกัด) กลุ่มแรกที่ผูกของ tenant เป็นกลุ่มแจ้งงานอัตโนมัติ กลุ่มเดิมที่ย้ายมาเป็นกลุ่มแจ้งงานด้วย เจ้าของเปลี่ยนได้ในหน้า Communication Center
- **การย้ายกลุ่มเดิม:** INSERT INTO line_groups จาก line_settings.crew_group_id แล้วคง `crew_group_id` ไว้อ่านได้ตลอดช่วงเปลี่ยนผ่าน (ไม่ drop ใน release นี้) เพื่อให้ rollback ได้
- `worker_assignments` ไม่เปลี่ยนโครงสร้าง ทีมถูกแตกเป็นแถวรายคนตอนบันทึก เงินเดือน/ต้นทุน/check-in ไม่ต้องแก้
- ระวัง: ถ้าสร้าง view ที่ใช้ `x.*` ต้องเช็กเรื่อง column freeze; ถ้า embed ตารางที่มี FK สองทาง ต้องระบุชื่อ constraint

## 4. การมอบหมายงาน (Assign.jsx)
- เพิ่มขั้น "เลือกทีม" (เลือกได้หลายทีม) ก่อนหรือคู่กับรายชื่อรายคน ผลลัพธ์คือชุดช่างรวม (dedupe ตาม worker_id เผื่อเลือกทีมแล้วติ๊กรายคนซ้ำ)
- ก่อนบันทึก ตรวจรายคน:
  - มีแถว worker_assignments วัน+กะเดียวกันอยู่แล้ว (ไซต์ใดก็ตาม) → ใช้กล่อง "พบ N กะที่มีงานอยู่แล้ว ยืนยันจะเขียนทับ" เดิม (handleWizardSubmit)
- ฝั่งเซิร์ฟเวอร์ต้องกันซ้ำด้วย: ตรวจ unique(worker_id, date, shift) ที่มีอยู่ (ถ้าไม่มีอยู่ ให้เสนอเพิ่มและถามก่อน) ห้ามพึ่งการตรวจฝั่ง UI อย่างเดียว

## 5. หน้าจัดการทีม
- ตั้งค่า → ทีมช่าง: สร้าง/แก้ชื่อ/ลบทีม, เพิ่ม-ลบสมาชิก (ค้นหาชื่อ) ถ้าช่างอยู่ทีมอื่นแล้ว แสดงชื่อทีมนั้นและถามว่าจะย้ายมาทีมนี้ไหม
- เจ้าของแก้ได้ แอดมินดูได้อย่างเดียว บังคับที่ RLS ไม่ใช่แค่ซ่อนปุ่ม
- ลบทีมไม่ลบ assignment ที่มอบหมายไปแล้ว

## 6. LINE หลายกลุ่ม
- **ผูกกลุ่ม:** ใช้ flow `group_link_code` เดิม แต่ผลลัพธ์ INSERT line_groups แทน UPDATE line_settings (รองรับกดผูกซ้ำหลายครั้งเพื่อเพิ่มกลุ่มใหม่) ถ้าเกินเพดาน tier ให้ตอบในกลุ่มว่าครบจำนวนแล้ว และไม่ผูก
- **line-webhook:** แก้การค้นหา tenant จาก group (index.ts ~1251) และจุดที่ใช้ตรวจ "กลุ่มนี้ของ tenant นี้" (~1528) ให้ค้นใน line_groups; รูป/ข้อความจากทุกกลุ่มที่ผูกแล้ว route เข้า tenant เดียวกัน
- **line-push-daily-assignments:** ส่งเฉพาะ line_group ที่ is_notify = true (ตาม A3) ผ่าน `withPushBudget` เดิม จำนวน push ต่อวันเท่าเดิม ไม่กระทบ line_push_caps
- **UI:** CommunicationCenter.jsx แสดงรายการกลุ่ม (ชื่อ, สถานะ) และ "ใช้ไปแล้ว X จาก Y กลุ่ม" ตาม tier แทนช่องเดียว; useGuideFacts.js ใช้ "มีอย่างน้อย 1 กลุ่ม" แทน crew_group_id
- Tenant เดิมที่มีกลุ่มเดียวต้องส่งงานต่อได้โดยไม่ต้องทำอะไร

## 7. ลำดับ rollout (ปลอดภัยต่อ tenant ที่ใช้งานจริง)
1. Migration เพิ่มตารางใหม่ + backfill กลุ่มเดิม (ถามเจ้าของก่อน apply, ทดสอบกับ tenant ทดสอบ)
2. Deploy edge functions ที่อ่านจาก line_groups (ไม่มี fallback ไป crew_group_id)
   - หมายเหตุ: ไอเดีย "fallback ไป crew_group_id" ถูกตัดทิ้งโดยตั้งใจ แล้วใช้ลำดับ deploy ที่เข้มงวด + backfill + query กระทบยอด (reconciliation) หลัง deploy แทน เพราะ fallback จะทำให้มีแหล่งข้อมูลความจริงสองที่ (crew_group_id กับ line_groups) ที่อาจไม่ตรงกัน
3. Deploy UI ทีม + Assign
4. ตรวจ ACL ของฟังก์ชัน/ตารางใหม่ (anon ต้องไม่เรียกได้) ตามบทเรียนหลัง restore
5. ในรอบถัดไปค่อยพิจารณา drop crew_group_id

## 8. การทดสอบ
- vitest: dedupe ชุดช่าง, ย้ายช่างข้ามทีม (PK กัน 2 ทีม), ตรวจชนกะ, เลือกกลุ่มแจ้งงานได้ 1 กลุ่มเสมอ, เพดานกลุ่มตาม tier
- ทดสอบ RLS: tenant A อ่าน/เขียนทีมของ tenant B ไม่ได้; ผู้ไม่ใช่เจ้าของเขียนทีมไม่ได้
- ทดสอบ migration backfill บนสำเนา/branch ก่อน ไม่ใช่ฐานจริง
- ตรวจ end-to-end กับ tenant ทดสอบ: 2 กลุ่ม, ผูกกลุ่มที่ 3 แล้วถูกปฏิเสธเมื่อ tier จำกัด 2, ส่งงานเข้าทุกกลุ่ม, ส่งรูปเข้า webhook จากแต่ละกลุ่ม

## 9. ความเสี่ยง
- ผู้ใช้จริงอยู่บน production: migration และ edge function มีผลทันทีที่ apply/deploy ต้องมีขั้นยืนยันกับเจ้าของทุกครั้ง
- ย้ายช่างข้ามทีมกลางวัน: งานที่มอบหมายแล้วไม่เปลี่ยนทีม แต่กลุ่มที่ได้ข้อความจะตามทีมปัจจุบัน
- ถ้าลบหรือยกเลิกกลุ่มแจ้งงาน ต้องมีกลุ่มแจ้งงานใหม่ (หรือเลือกใหม่) ไม่เช่นนั้นงานประจำวันเงียบหาย: ให้ UI บังคับเลือกกลุ่มใหม่ก่อนลบ ถ้ายังมีกลุ่มอื่นเหลือ
